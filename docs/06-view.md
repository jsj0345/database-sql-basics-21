# VIEW

## 1. 반복해서 사용하는 조회문을 관리하려면

여러 테이블을 조인하고 집계하는 SQL은 필요한 결과를 한 번에 보여줄 수 있지만, 동일한 조회가 자주 필요하다면 관리할 내용도 많아진다.

이번 학습에서는 `orders`와 `products`를 연결한 뒤 상품 카테고리별 주문 건수와 상태별 건수를 계산하는 조회를 사용했다. 이런 SQL을 여러 곳에서 각각 보관하면 같은 조회 조건을 반복해서 작성해야 하고, 집계 기준이 바뀔 때도 수정할 곳이 늘어난다.

또한 보고서 결과만 필요한 사용자에게 원본 테이블의 모든 정보를 보여줄 필요는 없다.

**조회문을 반복해서 작성하는 대신, 필요한 결과를 하나의 이름으로 사용할 수 있는 방법**이 뷰(`VIEW`)다.

---

## 2. 데이터 대신 조회 정의를 보관한다

뷰는 조회 결과를 별도로 저장하는 테이블이 아니라, `SELECT`문을 이름과 함께 등록하여 사용하는 데이터베이스 객체다.

뷰를 조회할 때는 저장된 조회 정의를 바탕으로 결과를 얻는다. 따라서 사용자는 원래의 긴 SQL을 직접 입력하지 않고도, 뷰를 테이블처럼 `SELECT`문에 사용할 수 있다.

```text
조회에 필요한 SELECT문 작성
→ VIEW 이름으로 등록
→ 이후 VIEW 이름을 이용해 결과 조회
```

핵심은 **조회 결과를 새로운 테이블에 복사하는 것이 아니라, 결과를 만드는 SQL을 재사용한다는 점**이다.

---

## 3. 뷰를 통해 줄일 수 있는 불편함

이번 내용에서 뷰의 용도는 크게 세 가지로 나눌 수 있었다.

- **조회 재사용:** 복잡한 SQL을 이용해야 할 때 매번 같은 문장을 다시 작성하지 않아도 된다.
- **노출 범위 제한:** 원본 테이블에 대한 직접 접근을 허용하지 않고, 뷰를 통해 필요한 행이나 컬럼만 제공할 수 있다.
- **변경 대응:** 원본 테이블의 일부 구조가 달라져도 뷰 정의를 조정하여 기존 조회 방식이 유지되도록 할 수 있는 경우가 있다.

즉, 뷰를 사용하면 조회를 작성하는 쪽과 실제 데이터를 관리하는 쪽 사이에 하나의 조회 정의를 둘 수 있다.

---

## 4. SELECT문에 이름 붙여 등록하기

뷰를 만드는 명령어는 `CREATE VIEW`다. 작성한 `SELECT`문을 어떤 이름으로 조회할지 지정한다.

```sql
CREATE VIEW 뷰이름 AS
SELECT ...;
```

원본 실습에서는 상품 카테고리별 주문 현황을 계산하는 `JOIN`, `GROUP BY`, `SUM(CASE ...)` 조회를 하나의 뷰로 등록했다.

이름에 `v_` 등의 접두사를 붙여 일반 테이블과 구분할 수도 있다. 뷰가 만들어졌다고 해서 원본 주문이나 상품 데이터를 별도로 복사해 저장하는 것은 아니다.

---

## 5. 등록한 뷰에서 결과 가져오기

생성한 뷰는 `FROM` 뒤에 이름을 적어 조회할 수 있다.

```sql
SELECT *
FROM v_category_order_status;
```

위 쿼리는 실습에서 등록한 카테고리별 주문 집계 결과를 확인하는 용도다.

처음에는 여러 테이블을 연결하고 조건별 건수를 계산하는 내용이 필요했지만, 뷰를 만든 뒤에는 **해당 조회를 어떤 이름으로 등록했는지만 알면 같은 형태의 결과를 요청할 수 있다.**

---

## 6. 저장된 조회 내용을 변경하기

기존 뷰의 조회 항목이나 계산 방식이 달라져야 한다면 `ALTER VIEW`로 정의를 변경할 수 있다.

```sql
ALTER VIEW 뷰이름 AS
SELECT ...;
```

이번 실습에서는 카테고리별 주문 건수와 상태별 건수에 더해, 상품 가격과 주문 수량을 이용한 매출 합계를 조회 항목에 포함했다.

기존 뷰를 사용하는 쿼리 자체를 새로 작성하는 대신, **뷰 내부의 SELECT 정의를 바꾸어 조회 결과에 새로운 컬럼을 추가한 것**이다.
